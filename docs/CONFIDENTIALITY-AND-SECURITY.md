# Confidentiality and security

Threats include accidental Git publication, source/internal data entering the public bundle, browser-memory access, malicious workbooks/ZIPs, credential exposure and misplaced trust in a static gate.

Controls include broad ignored input/output paths and Office/archive extensions; synthetic-only committed fixtures; browser-local processing; no telemetry or workbook-content logging; protected review; deliberate one-click decisions; separate project/internal workbooks; and fail-closed output when identities, exceptions, description decisions, collisions or reconciliation remain unresolved. Source context and decisions remain protected. The base public viewer is a constructed synthetic dataset.

The macro-enabled Job Register is read values-only. VBA is never executed, the source is never written back, and only validated project identity/search fields plus a fingerprint and load metadata persist locally. Fee values are not part of matching or publication. Invalid replacements do not overwrite the last valid catalogue.

Real Employee Register records live only in local browser storage and may be backed up to a controlled local file. Current and explicitly retained historical FY workbooks and the validated Job Register catalogue are stored in protected browser workstation storage; a valid newer copy replaces the corresponding record. The legacy annual-template store is removed on upgrade. Successfully opened encrypted employee publications use the same workstation-only storage boundary. Source timesheets and generated outputs remain in memory until download, except that a first-April project output also initialises the new Current FY record. Clearing browser/site storage removes workstation data; moving workstation requires controlled restoration. Internal and carry audit outputs contain protected source context and must be stored only in an approved local operational location.

Historical review mappings and decisions are also stored only in browser local storage. They contain workstation review metadata—not the administrative access code—and remain in the protected operator workflow. Exact workbook/sheet/cell evidence is retained behind deliberate details controls. An unchanged stable fingerprint may reuse an authorised decision; materially changed evidence is not silently suppressed.

The interim Employee Viewer plaintext is created and encrypted locally. Its encrypted package contains non-sensitive format/month metadata, PBKDF2 parameters, random salt, random AES-GCM IV and ciphertext. Plaintext is limited to approved project numbers/names, employee display names, employee project hours/project totals, and neutral month/hour/status information for Unknown or Excluded hours; original descriptions, reasons, internal categories (including Time in Lieu), register administration, source filenames/rows and audit traces are excluded. Only the encrypted publication JSON is uploaded to private Workers R2 storage: plaintext Employee Viewer data and Viewer access codes are never stored in R2. Short links contain only random publication IDs. A successfully opened encrypted publication may exist remotely in R2 and in the encrypted local workstation library. Worker/API compromise, link sharing, access-code sharing, browser extensions and screenshots remain risks.

The pilot uses a separate shared bearer-style Employee Viewer code. It has no individual identity, per-person revocation, central session or access audit. Employees can share the code; possession of both code and encrypted link grants access. Remembered codes and encrypted libraries rely on browser and workstation security. This interim authentication model is permitted only until approved company authentication, hosting, authorisation and key management replace it.

The shared Office Manager/Director gate is workstation convenience. Its SHA-256 digest is compiled into static JavaScript and is not a confidentiality boundary. Local storage and client JavaScript can be modified. The Admin token must never be reused as the Employee Viewer token.

Prohibited in Git, CI artifacts, screenshots, logs or Pages: real employee records, leave/sickness details, internal hours, plaintext employee/project-hour datasets, client/project data, source filenames, plaintext tokens, Office source files, generated real outputs, private QA locations and network-drive paths.
